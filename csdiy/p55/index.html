    1. 从 C 到可执行文件：编译过程¶

    假设源文件 main.c

    gcc -E main.c -o main.i
gcc -S main.i -o main.s
gcc -c main.s -o main.o
gcc main.o -o main

    整体流程：

    main.c -> main.i -> main.s -> main.o -> main

    对应阶段：

    1.1 预处理（Preprocessing）¶

    gcc -E

    处理：

    • #include
    • #define
    • #if/#ifdef
    • 宏展开
    • 删除注释

    输出：main.i

    1.2 编译（Compilation）¶

    gcc -S

    把 C 代码翻译成汇编代码。

    输出：main.s

    1.3 汇编（Assembly）¶

    gcc -c

    把汇编变成机器指令（目标文件）。

    输出：main.o

    1.4 链接（Linking）¶

    gcc

    把多个 .o 和库文件拼起来，解析符号引用，得到最终可执行文件。

    输出：可执行文件 main

    2. 机器级程序视角：CPU 到底在干什么¶

    CPU 执行程序本质上就是不断重复：

    1. 从 %rip 指向的地址取指令
    2. 解析指令
    3. 读寄存器 / 内存
    4. 做运算
    5. 写回寄存器 / 内存
    6. 更新 %rip

    所以第三章其实就是在学：

    C 里的变量、表达式、if、while、函数调用，在机器眼里到底变成了什么。

    3. 信息存储基础¶

    3.1 字节序（Endian）¶

    x86-64 采用 小端法（little-endian）。

    例：一个 32 位整数 0x12345678

    内存低地址到高地址存放顺序是：

    78 56 34 12

    低有效字节在低地址。

    3.2 基本数据大小（典型 LP64 模型）¶

    在 Linux x86-64 下常见大小：

    C 类型 字节数
    char 1
    short 2
    int 4
    long 8
    long long 8
    pointer 8
    float 4
    double 8

    注意：

    • long 在 64 位 Linux 是 8 字节
    • 但在 Windows 64 位常常还是 4 字节（LLP64）

    3.3 机器字（word）¶

    在 x86-64 中：

    • 一个机器字通常指 64 位 = 8 字节

    但历史上：

    • 16 位机器的 word = 2 字节
    • 32 位机器的 word = 4 字节

    4. x86-64 寄存器¶

    4.1 16 个通用寄存器¶

    64位 32位 16位 8位低位
    %rax %eax %ax %al
    %rbx %ebx %bx %bl
    %rcx %ecx %cx %cl
    %rdx %edx %dx %dl
    %rsi %esi %si %sil
    %rdi %edi %di %dil
    %rbp %ebp %bp %bpl
    %rsp %esp %sp %spl
    %r8 %r8d %r8w %r8b
    %r9 %r9d %r9w %r9b
    %r10 %r10d %r10w %r10b
    %r11 %r11d %r11w %r11b
    %r12 %r12d %r12w %r12b
    %r13 %r13d %r13w %r13b
    %r14 %r14d %r14w %r14b
    %r15 %r15d %r15w %r15b

    4.2 常见用途（System V AMD64 ABI）¶

    参数传递寄存器（前 6 个整数 / 指针参数）¶

    1. %rdi
    2. %rsi
    3. %rdx
    4. %rcx
    5. %r8
    6. %r9

    返回值¶

    • %rax

    栈指针¶

    • %rsp

    被调用者保存（callee-saved）¶

    • %rbx
    • %rbp
    • %r12
    • %r13
    • %r14
    • %r15

    调用者保存（caller-saved）¶

    • %rax
    • %rdi %rsi %rdx %rcx %r8 %r9
    • %r10 %r11

    4.3 caller-saved / callee-saved 的含义¶

    caller-saved¶

    调用者如果还想保留这些寄存器中的值，就得在 call 前自己保存。

    callee-saved¶

    被调用函数如果要修改这些寄存器，必须先保存，返回前恢复。

    5. AT&T 汇编语法（gcc 生成的汇编默认这种）¶

    5.1 基本规则¶

    寄存器¶

    前面带 %

    %rax

    立即数¶

    前面带 $

    $8

    内存地址¶

    写成：

    (%rdi)
8(%rbp)
(%rax,%rcx)
8(%rax,%rcx,4)

    5.2 操作数顺序¶

    AT&T 语法：

    op src, dst

    即：源在前，目的在后

    例如：

    movq %rax, %rbx

    表示：

    rbx = rax

    5.3 指令后缀表示操作数大小¶

    后缀 大小
    b 1 byte
    w 2 byte
    l 4 byte
    q 8 byte

    例：

    • movb
    • movw
    • movl
    • movq

    6. 操作数类型与寻址方式¶

    6.1 三类操作数¶

    1）Immediate（立即数）¶

    $8
$-3
$0x100

    2）Register（寄存器）¶

    %rax
%rdi

    3）Memory Reference（内存引用）¶

    (%rdi)
8(%rbp)
16(%rax,%rcx,8)

    6.2 通用地址公式¶

    Imm(base, index, scale)

    表示地址：

    addr = Imm + R[base] + R[index] * scale

    其中：

    • Imm：常数偏移
    • base：基址寄存器
    • index：变址寄存器
    • scale：比例因子，只能是 1,2,4,8

    6.3 常见例子¶

    数组 a[i]¶

    假设元素大小为 sizeof(a[0]) = 8

    &a[i] = base + i * 8

    汇编里可写：

    (%rax,%rcx,8)

    其中：

    • %rax = &a[0]
    • %rcx = i

    结构体字段 p->y¶

    若 y 偏移为 8：

    8(%rdi)

    栈上局部变量¶

    若某局部变量在 rbp-16：

    -16(%rbp)

    现代编译器也可能省略 %rbp，直接用 %rsp 相对寻址。

    7. 数据传送指令¶

    7.1 mov 系列¶

    基本形式¶

    movq S, D
movl S, D
movw S, D
movb S, D

    含义：把 S 的值复制到 D

    7.2 限制：普通 mov 不能内存到内存¶

    movq (%rax), (%rbx)   ; 错！

    必须借助寄存器中转：

    movq (%rax), %rcx
movq %rcx, (%rbx)

    7.3 扩展传送¶

    零扩展（unsigned）¶

    movzbw   ; byte -> word，零扩展
movzbl   ; byte -> int
movzbq   ; byte -> quad
movzwl   ; word -> int
movzwq   ; word -> quad

    符号扩展（signed）¶

    movsbw
movsbl
movsbq
movswl
movswq
movslq   ; int -> long/quad

    比如：

    movsbl (%rax), %edx

    表示把一个有符号字节读出来，符号扩展成 32 位放入 %edx

    7.4 movl 的特殊性¶

    写 32 位寄存器会清空高 32 位：

    movl $-1, %eax

    结果：

    rax = 0x00000000ffffffff

    不是全 64 位的 -1。

    若要得到 64 位 -1，要用：

    movq $-1, %rax

    7.5 cltq¶

    常见于把 %eax 符号扩展到 %rax

    cltq

    等价于：

    movslq %eax, %rax

    8. 算术与逻辑指令¶

    8.1 加减¶

    addq S, D   ; D = D + S
subq S, D   ; D = D - S

    例：

    addq %rax, %rbx

    表示：

    rbx += rax

    8.2 乘法¶

    无符号/普通低位乘法¶

    imulq S, D

    表示：

    D = D * S

    也有三操作数形式：

    imulq $8, %rax, %rdx

    表示：

    rdx = rax * 8

    8.3 除法（相对难记）¶

    idiv¶

    被除数是隐含的：

    • 64 位除法：被除数在 %rdx:%rax
    • 商放 %rax
    • 余数放 %rdx

    例如：

    cqto
idivq %rbx

    结果：

    • %rax = (rdx:rax) / rbx
    • %rdx = (rdx:rax) % rbx

    对应辅助指令：

    • cqto：rax -> rdx:rax 符号扩展
    • cltd / cdq：32 位版本

    8.4 逻辑运算¶

    andq S, D   ; D &= S
orq  S, D   ; D |= S
xorq S, D   ; D ^= S
notq D      ; D = ~D

    常见技巧：

    xorq %rax, %rax

    把 %rax 置 0。

    8.5 求负¶

    negq %rax

    表示：

    rax = -rax

    9. 移位指令¶

    9.1 左移 / 右移¶

    salq k, D   ; 左移（与 shl 等价）
shlq k, D   ; 左移
sarq k, D   ; 算术右移（保留符号位）
shrq k, D   ; 逻辑右移（高位补0）

    9.2 区别：sar vs shr¶

    sar¶

    适用于有符号数，右移时高位补符号位。

    shr¶

    适用于无符号数，右移时高位补 0。

    9.3 移位量来源¶

    可以是：

    • 立即数
    • %cl（注意是 %rcx 的低 8 位）

    例如：

    salq $3, %rax
sarq %cl, %rax

    10. leaq：超高频指令¶

    10.1 本质¶

    leaq S, D

    把 地址表达式的值 计算出来放进寄存器。

    注意：

    • 它不访问内存
    • 只是做地址计算

    10.2 例子¶

    leaq 8(%rax,%rcx,4), %rdx

    等价于：

    rdx = rax + rcx * 4 + 8

    10.3 为什么它常被拿来做普通算术¶

    因为它支持：

    base + index * scale + offset

    所以编译器常用它来实现：

    • x + 3
    • x * 5（x + x*4）
    • x * 9 + 7 等

    例如：

    leaq (%rax,%rax,4), %rdx

    得到：

    rdx = rax * 5

    11. 条件码（Condition Codes）¶

    CPU 在执行很多算术/逻辑指令后，会自动设置条件码标志位。

    11.1 主要标志位¶

    ZF（Zero Flag）¶

    结果是否为 0。

    SF（Sign Flag）¶

    结果是否为负（最高位是否为 1）。

    CF（Carry Flag）¶

    无符号运算是否发生进位/借位。

    OF（Overflow Flag）¶

    有符号运算是否溢出。

    11.2 哪些指令会设置条件码¶

    通常这些会设置：

    • add
    • sub
    • cmp
    • test
    • and
    • or
    • xor

    通常这些不会设置：

    • mov
    • lea

    11.3 cmp¶

    cmpq S, D

    本质做的是：

    D - S

    但不保存结果，只设置条件码。

    例如：

    cmpq %rax, %rbx

    表示比较：

    rbx - rax

    11.4 test¶

    testq S, D

    本质做：

    D & S

    不保存结果，只设置条件码。

    常见用途：

    testq %rax, %rax

    相当于判断 %rax 是否为 0。

    12. 条件跳转（Jump）¶

    12.1 无条件跳转¶

    jmp label

    直接跳过去。

    12.2 条件跳转¶

    根据条件码决定跳不跳。

    常见跳转指令：

    指令 含义
    je / jz 等于 / 为0
    jne / jnz 不等于 / 不为0
    js 负
    jns 非负
    jg 大于（有符号）
    jge 大于等于（有符号）
    jl 小于（有符号）
    jle 小于等于（有符号）
    ja 大于（无符号）
    jae 大于等于（无符号）
    jb 小于（无符号）
    jbe 小于等于（无符号）

    12.3 有符号比较条件¶

    假设执行了：

    cmpq S, D

    即比较 D 和 S

    相等¶

    je

    条件：

    ZF = 1

    不等¶

    jne

    条件：

    ZF = 0

    小于（signed）¶

    jl

    条件：

    SF ^ OF = 1

    小于等于（signed）¶

    jle

    条件：

    (SF ^ OF) | ZF

    大于（signed）¶

    jg

    条件：

    !(SF ^ OF) & !ZF

    大于等于（signed）¶

    jge

    条件：

    SF ^ OF = 0

    12.4 无符号比较条件¶

    小于（unsigned）¶

    jb

    条件：

    CF = 1

    小于等于（unsigned）¶

    jbe

    条件：

    CF | ZF

    大于（unsigned）¶

    ja

    条件：

    !CF & !ZF

    大于等于（unsigned）¶

    jae

    条件：

    CF = 0

    12.5 signed / unsigned 千万别混¶

    这是最经典坑点之一。

    • jl/jg/jle/jge：有符号
    • jb/ja/jbe/jae：无符号

    比如 -1 < 1：

    • 有符号下是对的
    • 无符号下 0xffffffffffffffff > 1

    13. set 指令：把条件变成 0/1¶

    13.1 形式¶

    setcc D

    根据条件码，把目标字节寄存器/内存设置为：

    • 条件成立：1
    • 否则：0

    常见：

    • sete
    • setne
    • setl
    • setg
    • seta
    • setb

    13.2 例子¶

    cmpq %rsi, %rdi
setg %al
movzbl %al, %eax

    含义：

    eax = (rdi > rsi) ? 1 : 0;

    注意：

    • setcc 只写 1 个字节
    • 后面常配合 movzbl 扩成 32 位整数

    14. 条件传送（Conditional Move）¶

    比跳转更“平滑”的一种条件控制方式，常用于减少分支。

    14.1 形式¶

    cmovcc S, D

    若条件成立，则：

    D = S

    否则 D 不变。

    14.2 常见种类¶

    • cmove
    • cmovne
    • cmovl
    • cmovg
    • cmovge
    • cmova
    • cmovb

    14.3 用途¶

    例如：

    x = (a < b) ? y : z;

    可能编译成：

    movq %z, %rax
cmpq %b, %a
cmovl %y, %rax

    这样避免分支预测失败带来的代价。

    15. 用跳转实现 if / while / for¶

    15.1 if 语句¶

    C：

    if (x < y) a = b;

    可能变成：

    cmpq %rsi, %rdi      ; 比较 x 和 y
jge .L1              ; 若 x >= y，跳过
movq %rbx, %rax      ; a = b
.L1:

    15.2 if-else¶

    C：

    if (x < y) a = 1;
else a = 2;

    典型模式：

    cmpq %rsi, %rdi
jge .Lelse
movl $1, %eax
jmp .Lend
.Lelse:
movl $2, %eax
.Lend:

    15.3 while 循环¶

    C：

    while (x > 0) {
    x--;
}

    典型：

    .Ltest:
cmpq $0, %rdi
jle .Ldone
subq $1, %rdi
jmp .Ltest
.Ldone:

    15.4 do-while¶

    C：

    do {
    x--;
} while (x > 0);

    典型：

    .Lloop:
subq $1, %rdi
cmpq $0, %rdi
jg .Lloop

    15.5 for¶

    本质上编译后和 while 差不多。

    16. switch 与跳转表（Jump Table）¶

    当 switch 分支很多且 case 值比较密集时，编译器常用跳转表优化。

    16.1 思想¶

    不是一层层 cmp + je，而是：

    1. 检查 x 是否在合法范围
    2. 用 x 作为下标查表
    3. 取出目标地址
    4. 直接跳过去

    16.2 伪代码¶

    switch(x) {
  case 0: ...
  case 1: ...
  case 2: ...
  default: ...
}

    可能类似：

    cmpq $2, %rdi
ja .Ldefault
jmp *.Ltable(,%rdi,8)

    其中 .Ltable 存放各 case 的代码地址。

    16.3 什么时候不会用跳转表¶

    • case 很少
    • case 值很稀疏
    • 优化级别低

    17. 过程（函数）调用机制¶

    这是第三章的绝对大头。

    17.1 call¶

    call func

    做两件事：

    1. 把下一条指令地址压栈（返回地址）
    2. 跳到 func

    17.2 ret¶

    ret

    做两件事：

    1. 从栈顶弹出返回地址
    2. 跳回去

    17.3 参数传递规则（整数/指针）¶

    前 6 个参数：

    1. %rdi
    2. %rsi
    3. %rdx
    4. %rcx
    5. %r8
    6. %r9

    更多参数放栈上。

    17.4 返回值¶

    通常通过 %rax 返回。

    若返回较大结构体，规则会更复杂。

    18. 栈帧（Stack Frame）¶

    18.1 栈的方向¶

    栈从 高地址向低地址 增长。

    所以：

    pushq %rax

    会使 %rsp 变小 8。

    18.2 push / pop¶

    pushq %rax

    等价于：

    rsp -= 8
M[rsp] = rax

    popq %rbx

    等价于：

    rbx = M[rsp]
rsp += 8

    18.3 典型函数序言 / 结语¶

    序言（prologue）¶

    pushq %rbp
movq %rsp, %rbp
subq $32, %rsp

    含义：

    1. 保存旧 %rbp
    2. 建立新栈帧基址
    3. 给局部变量留空间

    结语（epilogue）¶

    leave
ret

    其中 leave 等价于：

    movq %rbp, %rsp
popq %rbp

    18.4 现代编译器可能省略 %rbp¶

    开启优化后，编译器常常不使用帧指针 %rbp，而直接以 %rsp 寻址，腾出一个寄存器可用。

    18.5 栈对齐¶

    System V AMD64 ABI 要求：

    在执行 call 前，栈通常应满足 16 字节对齐要求。

    这个在手写汇编 / 分析函数调用时很重要。

    19. 递归为什么可行¶

    递归本质上就是：

    • 每次调用都创建一个新的栈帧
    • 局部变量、返回地址、保存的寄存器都放在自己这一层的栈帧里
    • 彼此互不干扰

    所以递归并不神秘，就是普通函数调用叠起来。

    20. 数组的机器级表示¶

    20.1 一维数组¶

    设：

    long a[10];

    则：

    &a[i] = base + i * 8

    因为 sizeof(long)=8

    访问 a[i] 本质是：

    • 先算地址
    • 再读/写内存

    20.2 二维数组¶

    设：

    int A[R][C];

    按 行优先（row-major） 存储。

    地址公式：

    &A[i][j] = base + (i*C + j) * sizeof(int)

    这个式子特别重要。

    20.3 多维数组本质¶

    多维数组访问就是把下标展开成线性偏移。

    21. 结构体与联合体¶

    21.1 结构体字段偏移¶

    例：

    struct S {
    int x;     // 4
    char c;    // 1
    long y;    // 8
};

    结构体里字段不是简单紧凑排的，要考虑 对齐（alignment）。

    21.2 对齐规则¶

    每个字段通常按其大小或 ABI 规定对齐，例如：

    • char 对齐到 1
    • int 对齐到 4
    • long 对齐到 8

    因此中间可能会插入 padding。

    21.3 例子分析¶

    上面这个结构体：

    struct S {
    int x;     // offset 0
    char c;    // offset 4
    // padding 3 bytes
    long y;    // offset 8
};

    总大小通常为 16。

    21.4 访问结构体字段¶

    若 %rdi 存放 p，则：

    • p->x：0(%rdi)
    • p->c：4(%rdi)
    • p->y：8(%rdi)

    21.5 联合体（union）¶

    联合体所有字段共享同一块内存。

    union U {
    int x;
    char c[4];
};
    • 所有字段起始地址相同
    • 大小取决于最大字段，并考虑对齐

    22. 指针、数组、地址运算¶

    22.1 指针加法¶

    p + i

    不是字节相加，而是：

    地址 + i * sizeof(*p)

    所以编译器常用 lea 或带比例因子的寻址来实现。

    22.2 *p¶

    本质：

    • 先把 p 当地址
    • 再访问该地址中的内容

    22.3 &x¶

    本质：

    • 取对象 x 的地址
