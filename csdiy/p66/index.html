    CS:APP 第 4 章：Y86-64 处理器体系结构复习笔记

    主线：先定义软件能看到的 ISA，再把每条指令拆成固定阶段构造 SEQ，最后在阶段之间插入流水线寄存器得到 PIPE，并通过转发、暂停和气泡保证并行执行仍与顺序语义一致。

    0. 整章知识地图

    软件程序
   │
   ▼
ISA：规定“机器应该表现成什么样”
   │  Y86-64 状态、指令、编码、异常
   ▼
SEQ：一次完整执行一条指令
   │  Fetch → Decode → Execute → Memory → Write Back → Update PC
   ▼
PIPE：多条指令重叠执行
   │  F/D/E/M/W 流水线寄存器
   ▼
冒险处理
   ├─ 数据冒险：forward / stall / bubble
   └─ 控制冒险：branch prediction / recovery / ret stall
   ▼
性能分析：CPI、吞吐量、气泡代价

    本章最重要的三个问题

    1. 一条机器指令需要哪些硬件动作？
    2. 不同指令怎样复用同一套数据通路？
    3. 多条指令重叠执行时，怎样维持原本的顺序语义？

    1. ISA：软件与硬件之间的接口

    1.1 什么是 ISA

    ISA（Instruction Set Architecture，指令集体系结构）位于软件和硬件之间：

    软件：只依赖 ISA 规定的行为
──────── ISA ────────
硬件：可以用不同电路实现同一 ISA

    ISA 规定的是机器对程序员可见的行为，例如：

    • 有哪些寄存器；
    • 指令能够完成什么操作；
    • 指令如何编码；
    • 条件码如何变化；
    • PC 如何更新；
    • 出错或停止时机器处于什么状态。

    ISA 不规定处理器内部必须使用 SEQ、五级流水线、几条转发线或哪一种晶体管。

    同一份 Y86-64 程序可以在 SEQ 和 PIPE 上运行，因为二者实现相同的 ISA。

    1.2 Y86-64 的程序员可见状态

    状态 作用
    15 个 64 位程序寄存器 保存整数、地址、栈指针等；没有 %r15
    PC 当前/下一条指令地址
    条件码 ZF/SF/OF 供条件传送和条件跳转判断
    Memory 保存指令、数据和栈
    Stat 处理器运行状态

    条件码

    • ZF（Zero Flag）：结果是否为 0；
    • SF（Sign Flag）：结果最高位是否为 1；
    • OF（Overflow Flag）：有符号运算是否溢出。

    通常只有 OPq 算术/逻辑指令更新条件码。

    状态码

    值 名称 含义
    1 AOK 正常运行
    2 HLT 遇到 halt
    3 ADR 非法内存地址
    4 INS 非法指令编码

    2. Y86-64 指令集

    2.1 数据传送指令

    指令 语义 数据方向
    rrmovq rA, rB R[rB] ← R[rA] 寄存器 → 寄存器
    irmovq V, rB R[rB] ← V 立即数 → 寄存器
    rmmovq rA, D(rB) M[R[rB]+D] ← R[rA] 寄存器 → 内存
    mrmovq D(rB), rA R[rA] ← M[R[rB]+D] 内存 → 寄存器

    Y86-64 不支持一般形式的“内存直接到内存”，也没有 x86-64 那样丰富的寻址方式。

    2.2 算术和逻辑指令 OPq

    统一形式：

    OPq rA, rB

    语义：

    R[rB] ← R[rB] OP R[rA]
    ifun 指令 运算
    0 addq 加法
    1 subq rB - rA
    2 andq 按位与
    3 xorq 按位异或

    这些指令会根据结果设置 ZF/SF/OF。

    2.3 条件传送和条件跳转

    条件传送

    cmovXX rA, rB

    条件成立时：

    R[rB] ← R[rA]

    条件不成立时：不写寄存器。

    条件跳转

    jXX Dest

    条件成立：

    PC ← Dest

    条件不成立：

    PC ← valP

    ifun 条件编码

    ifun 无条件/条件 条件表达式
    0 rrmovq / jmp true
    1 cmovle / jle (SF xor OF) or ZF
    2 cmovl / jl SF xor OF
    3 cmove / je ZF
    4 cmovne / jne not ZF
    5 cmovge / jge not(SF xor OF)
    6 cmovg / jg not(SF xor OF) and not ZF

    为什么有符号大小比较必须使用 SF xor OF？因为发生有符号溢出时，结果符号位不能单独代表真实大小关系，OF 用来修正 SF。

    2.4 栈和过程控制

    指令 核心语义
    pushq rA %rsp -= 8; M[%rsp] = R[rA]
    popq rA R[rA] = M[%rsp]; %rsp += 8
    call Dest %rsp -= 8; M[%rsp] = valP; PC = Dest
    ret PC = M[%rsp]; %rsp += 8

    call 为什么把 valP 写入内存

    valP 是 call 后一条指令的地址，即返回地址：

    M[%rsp - 8] ← valP
PC           ← valC / Dest

    ret 为什么比较特殊

    ret 的目标 PC 存在栈内存中：

    PC ← M[%rsp]

    只有访存阶段完成后才知道返回地址，因此它会在流水线中引发控制冒险。

    3. 指令编码

    3.1 基本格式

    第一字节固定为：

    高 4 位：icode（指令类别）
低 4 位：ifun （同类指令中的具体功能）

    后面可能包含：

    寄存器字节：rA | rB
8 字节常数：valC

    icode 总表

    icode 指令类
    0 halt
    1 nop
    2 rrmovq / cmovXX
    3 irmovq
    4 rmmovq
    5 mrmovq
    6 OPq
    7 jXX
    8 call
    9 ret
    A pushq
    B popq

    3.2 寄存器编码

    编号 寄存器 编号 寄存器
    0 %rax 8 %r8
    1 %rcx 9 %r9
    2 %rdx A %r10
    3 %rbx B %r11
    4 %rsp C %r12
    5 %rbp D %r13
    6 %rsi E %r14
    7 %rdi F RNONE（无寄存器）

    F 不是 %r15，而是“这个位置不需要寄存器”。

    例如：

    irmovq $8, %r8

    寄存器字节为：

    F8

    因为该指令没有源寄存器，rA = F，目标寄存器 %r8 编号为 8。

    3.3 指令长度

    指令 长度
    halt、nop、ret 1 字节
    rrmovq/cmovXX、OPq、pushq、popq 2 字节
    jXX、call 9 字节
    irmovq、rmmovq、mrmovq 10 字节

    处理器根据 icode 判断是否存在：

    need_regids：是否需要寄存器字节
need_valC：是否需要 8 字节常数

    然后计算：

    valP = PC + 指令长度

    4. 硬件基础：组合逻辑与时序逻辑

    4.1 组合逻辑

    输出只由当前输入决定，没有历史状态：

    逻辑门、加法器、ALU、多路选择器、条件判断逻辑

    多路选择器可理解为：

    select = 0 → 输出 a
select = 1 → 输出 b

    HCL 中的写法类似：

    word x = [
    condition1 : value1;
    condition2 : value2;
    1          : default;
];

    4.2 时序逻辑

    输出不仅与当前输入有关，还保存历史状态：

    PC、程序寄存器、条件码、流水线寄存器、存储器

    D 触发器在时钟边沿把输入 D 保存到输出 Q：

    时钟上升沿：Q ← D
其余时间：Q 保持不变

    Verilog 对应关系

    • assign：描述组合逻辑；
    • always @(posedge clock)：描述时钟边沿发生的状态更新；
    • 模块实例化：复用已有硬件模块。

    为什么需要区分

    在一个周期内：

    1. 组合逻辑根据旧状态不断传播并稳定；
    2. 到达时钟边沿时，状态元件一次性保存新值；
    3. 下一周期再根据新状态计算。

    这保证了处理器不会在同一周期内“边算边覆盖”导致混乱。

    5. SEQ：Y86-64 的顺序实现

    5.1 六个逻辑阶段

    Fetch → Decode → Execute → Memory → Write Back → Update PC
 取指      译码       执行       访存        写回        更新 PC

    虽然逻辑上分成六个阶段，但 SEQ 中一条指令的这些阶段在一个很长的时钟周期内依次经过组合逻辑，周期末统一更新状态。

    5.2 各阶段的职责

    Fetch：取指

    输入：PC

    输出：

    • icode、ifun；
    • 可选的 rA、rB；
    • 可选的 8 字节常数 valC；
    • 顺序下一条地址 valP；
    • 指令是否合法、取指地址是否有效。

    关键硬件：

    Instruction Memory
Split：拆出 icode/ifun
Align：对齐并取出 rA/rB/valC
PC Increment：计算 valP

    Decode：译码和读寄存器

    先根据 icode 选择：

    srcA、srcB：需要读取哪些寄存器
dstE、dstM：之后会写哪些寄存器

    寄存器文件支持：

    两个读端口 A/B
两个写端口 E/M

    读出的值记为：

    valA = R[srcA]
valB = R[srcB]

    Execute：执行

    ALU 主要完成三类任务：

    1. 算术/逻辑运算；
    2. 计算有效地址；
    3. 栈指针加减 8。
    valE = ALU(aluA, aluB, alufun)

    同时可能：

    • 更新条件码 CC；
    • 根据 CC + ifun 计算条件是否成立 Cnd；
    • 条件传送失败时把 dstE 改为 RNONE。

    Memory：访存

    决定三个问题：

    是否读/写？
地址是什么？
写入的数据是什么？
    指令 内存地址 写入数据/读出数据
    rmmovq valE 写 valA
    mrmovq valE 读出 valM
    pushq valE 写 valA
    popq valA（旧 %rsp） 读出 valM
    call valE 写 valP
    ret valA（旧 %rsp） 读出返回地址 valM

    Write Back：写回

    最多执行两次寄存器写入：

    R[dstE] ← valE
R[dstM] ← valM

    例如 popq %rsp 可能同时写 %rsp：

    • dstE=%rsp，写入更新后的栈指针 valE；
    • dstM=%rsp，写入弹出的值 valM。

    在寄存器文件实现中需要明确两个写端口的优先级，以匹配 ISA 语义。

    Update PC：更新 PC

    情况 新 PC
    call valC
    条件跳转且 Cnd=1 valC
    ret valM
    其他情况 valP 
    newPC =
    call              ? valC :
    jxx && Cnd        ? valC :
    ret               ? valM :
                        valP

    6. 常见指令的阶段级语义

    6.1 总表

    指令 Decode Execute Memory Write Back PC
    rrmovq/cmovXX valA=R[rA] valE=valA，判断 Cnd - 条件成立时 R[rB]=valE valP
    irmovq - valE=valC - R[rB]=valE valP
    rmmovq valA=R[rA],valB=R[rB] valE=valB+valC M[valE]=valA - valP
    mrmovq valB=R[rB] valE=valB+valC valM=M[valE] R[rA]=valM valP
    OPq valA=R[rA],valB=R[rB] valE=valB OP valA，更新 CC - R[rB]=valE valP
    jXX - 根据 CC 得到 Cnd - - Cnd?valC:valP
    call valB=R[%rsp] valE=valB-8 M[valE]=valP R[%rsp]=valE valC
    ret valA=valB=R[%rsp] valE=valB+8 valM=M[valA] R[%rsp]=valE valM
    pushq valA=R[rA],valB=R[%rsp] valE=valB-8 M[valE]=valA R[%rsp]=valE valP
    popq valA=valB=R[%rsp] valE=valB+8 valM=M[valA] %rsp=valE,R[rA]=valM valP

    6.2 关键控制信号速查

    源寄存器

    srcA =
  rA   for rrmovq/cmovXX, rmmovq, OPq, pushq
  %rsp for popq, ret
  RNONE otherwise

srcB =
  rB   for OPq, rmmovq, mrmovq
  %rsp for pushq, popq, call, ret
  RNONE otherwise

    目的寄存器

    dstE =
  rB   for rrmovq/cmovXX, irmovq, OPq
  %rsp for pushq, popq, call, ret
  RNONE otherwise

dstM =
  rA   for mrmovq, popq
  RNONE otherwise

    ALU 输入

    aluA =
  valA for rrmovq/cmovXX, OPq
  valC for irmovq, rmmovq, mrmovq
  -8   for call, pushq
  +8   for ret, popq

aluB =
  valB for rmmovq, mrmovq, OPq, call, pushq, ret, popq
  0    for rrmovq/cmovXX, irmovq

    alufun = ifun 仅用于 OPq
alufun = ADD  用于其他指令

    内存控制

    mem_read  = mrmovq || popq || ret
mem_write = rmmovq || pushq || call

    为什么统一成多路选择器

    处理器不是给每一条指令单独造一套电路，而是让所有指令共享：

    一套寄存器文件
一套 ALU
一套数据内存

    icode/ifun 产生控制信号，决定本周期数据走哪条路径。

    7. 从 SEQ 到流水线

    7.1 为什么做流水线

    SEQ 的时钟周期必须覆盖整条最长组合逻辑路径：

    取指 + 读寄存器 + ALU + 访存 + 写回控制 + 寄存器开销

    即使当前指令只用其中一部分，也必须等待最长路径结束。

    流水线把大任务切成多个较短阶段，在阶段之间加入时钟寄存器：

    F | D | E | M | W

    不同指令可以同时占据不同阶段。

    7.2 吞吐量与延迟

    不流水化示例

    组合逻辑延迟：300 ps
寄存器开销： 20 ps
时钟周期：   320 ps
吞吐量：约 1/320ps = 3.12 GIPS

    分成三级，每级 100 ps

    每级时钟周期：100 + 20 = 120 ps
稳态吞吐量：约 1/120ps = 8.33 GIPS
单条指令延迟：3 × 120 = 360 ps

    结论：

    • 流水线主要提高吞吐量；
    • 单条指令的端到端延迟不一定下降，甚至会增加；
    • 启动和排空流水线需要额外周期。

    7.3 非均匀划分与深流水线

    若阶段延迟是：

    50 ps、150 ps、100 ps

    时钟周期由最慢阶段决定：

    150 + 20 = 170 ps

    因此流水线分段越均衡，效率越高。

    继续把阶段切得更细，理论频率提高，但每一级都有寄存器开销：

    级数越深
→ 寄存器开销占比越大
→ 冒险惩罚的周期数可能增加
→ 性能收益递减

    这就是深流水线的 diminishing returns（收益递减）。

    8. PIPE：五级流水线硬件结构

    8.1 流水线寄存器

    阶段之间必须保存当前指令下一阶段所需的信息：

    F 寄存器

    predPC

    D 寄存器

    stat, icode, ifun, rA, rB, valC, valP

    E 寄存器

    stat, icode, ifun, valC, valA, valB,
dstE, dstM, srcA, srcB

    M 寄存器

    stat, icode, Cnd, valE, valA, dstE, dstM

    W 寄存器

    stat, icode, valE, valM, dstE, dstM

    为什么要把 srcA/srcB/dstE/dstM 一起传下去

    流水线后续需要知道：

    • 当前指令读取了谁；
    • 当前指令准备写谁；
    • 转发和冒险检测该比较哪些寄存器编号。

    只保存数值而不保存寄存器编号，控制逻辑无法判断数据关系。

    8.2 流水线寄存器的三种操作

    正常加载

    下一个状态 ← 当前组合逻辑输出

    Stall（暂停）

    下一个状态 ← 保持旧状态

    含义：当前指令留在该阶段，不向前移动。

    Bubble（气泡）

    下一个状态 ← nop 状态

    典型做法是把：

    icode = INOP
dstE = dstM = RNONE

    使该流水线槽位不会写寄存器、写内存或修改条件码。

    stall 是把原指令按住；bubble 是让某个本应进入的槽位变成无副作用的空操作。

    9. 数据依赖、数据冒险和转发

    9.1 依赖与冒险不是一回事

    irmovq $10, %rdx
irmovq $3,  %rax
addq   %rdx, %rax

    addq 需要前两条指令产生的数据，因此存在 RAW（Read After Write）数据依赖。

    • 数据依赖：程序语义关系，即后指令必须使用前指令的结果；
    • 数据冒险：流水线执行时，消费者读取数据的时间早于生产者写回数据的时间。

    顺序处理器也有依赖，但通常没有流水线时间冲突。

    9.2 为什么等待写回很浪费

    若完全不转发，消费者必须等生产者到 W 阶段写回寄存器文件，期间插入多个气泡。

    但很多结果更早已经出现：

    • ALU 结果在 E 阶段末得到 e_valE；
    • 更早指令的结果位于 M_valE、W_valE；
    • 内存读结果在 M 阶段末得到 m_valM，之后有 W_valM。

    所以可以直接把这些值送到 Decode 阶段，而不必等寄存器文件更新。

    9.3 转发（Forwarding / Bypassing）

    Decode 产生 d_valA/d_valB 时，不一定使用寄存器文件原值，而是在多个来源中选择最新值。

    优先级的思想：离当前指令越近的生产者越新，应优先。

    d_valA：
1. call/jXX 特殊取 D_valP
2. d_srcA == e_dstE → e_valE
3. d_srcA == M_dstM → m_valM
4. d_srcA == M_dstE → M_valE
5. d_srcA == W_dstM → W_valM
6. d_srcA == W_dstE → W_valE
7. 否则读取寄存器文件

    d_valB 采用同类比较，但没有 call/jXX → valP 的特殊规则。

    为什么 jXX/call 的 valA 保存 valP

    • call 需要把 valP 压栈；
    • 预测跳转失败时，流水线需要 valP 恢复到顺序路径。

    10. Load/Use 冒险

    10.1 典型代码

    mrmovq 0(%rdx), %rax
addq   %rbx, %rax

    第一条指令从内存产生 %rax，第二条立即使用 %rax。

    为什么普通转发仍来不及

    mrmovq 的数据：到 M 阶段末才得到 m_valM
addq 的输入：进入 E 阶段时已经必须准备好

    如果两条指令紧邻：

    周期 T+1：mrmovq 在 M，addq 已经在 E

    两者处于同一周期，内存值在周期末才出现，无法在周期开始前作为 addq 的 E 阶段输入。

    10.2 正确控制

    检测条件：

    E_icode ∈ { IMRMOVQ, IPOPQ }
and E_dstM ∈ { d_srcA, d_srcB }

    控制动作：

    F_stall  = 1
D_stall  = 1
E_bubble = 1

    时序变化：

    周期 T：
D = addq
E = mrmovq

时钟边沿后：
D = addq      （被 stall，原地等待）
E = nop       （插入 bubble）
M = mrmovq    （正常向前，去读取内存）

下一周期：
m_valM 可以转发给仍在 D 的 addq

    11. 控制冒险

    11.1 根源

    取指阶段每个周期都必须知道下一个 PC，但分支或返回指令的真实目标可能尚未确定。

    数据冒险：下一条是谁已经知道，但数据还没准备好。
控制冒险：连下一条应该取谁都不知道。

    11.2 条件跳转与分支预测

    Y86 PIPE 使用简单策略：

    遇到 jXX：预测 Taken，F_predPC = valC
遇到 call：F_predPC = valC
其他指令：F_predPC = valP

    条件跳转到 E 阶段才能根据 CC 得到 e_Cnd。

    预测正确

    预测路径继续执行，无额外代价。

    预测错误

    由于默认预测 Taken，错误情况通常是：

    E_icode == IJXX && !e_Cnd

    此时：

    • 分支后的错误路径指令已经进入 D；
    • 另一条错误指令正在 F；
    • 必须把它们清成气泡。

    控制动作：

    D_bubble = 1
E_bubble = 1

    错误预测通常产生 2 个气泡。

    正确 PC 从流水线中的分支携带回来：

    M_icode == IJXX && !M_Cnd → f_pc = M_valA

    这里 M_valA 保存的就是该分支的 valP，即不跳转时的顺序地址。

    11.3 ret 冒险

    ret 的返回目标：

    valM = M[%rsp]

    直到 ret 进入 M 阶段并访问内存，下一 PC 才知道。

    当 ret 位于：

    D、E 或 M 阶段

    Fetch 暂停：

    F_stall = 1

    同时不断向 D 插入 bubble，防止错误指令进入流水线。

    当 ret 到达 W 阶段：

    f_pc = W_valM

    从返回地址恢复取指。

    典型返回惩罚为 3 个气泡。

    为什么 call 没有同样的问题

    call 的目标地址 valC 在取指阶段已从指令中读出，因此可以立即预测下一 PC；不确定的是 ret，因为目标藏在运行时栈内存中。

    12. 流水线控制信号总表

    先定义三个事件：

    load_use =
    E_icode ∈ { IMRMOVQ, IPOPQ }
    && E_dstM ∈ { d_srcA, d_srcB }

mispredict =
    E_icode == IJXX && !e_Cnd

ret_in_pipe =
    IRET ∈ { D_icode, E_icode, M_icode }

    经典控制逻辑：

    F_stall  = load_use || ret_in_pipe

D_stall  = load_use

D_bubble = mispredict
           || (!load_use && ret_in_pipe)

E_bubble = mispredict || load_use

    12.1 为什么 D_bubble 中有 !load_use

    同一个流水线寄存器不能同时：

    stall：保留旧指令
bubble：改成 nop

    当 Load/Use 和 ret 条件同时出现时，D 必须优先 stall，保留正在等待数据的指令。因此：

    D_bubble 只有在“不是 load/use”时才因 ret 生效

    这体现了控制条件组合时必须明确优先级。

    12.2 PC 选择优先级

    f_pc =
1. 分支预测失败恢复：M_valA
2. ret 返回地址：W_valM
3. 正常预测地址：F_predPC

    优先级不能随意交换，因为较老指令对真实控制流拥有更高权威。

    13. 异常在流水线中的处理思路

    异常指令不能让比它更新的指令先修改体系结构状态。

    因此状态码 stat 会随指令沿流水线传播，通常在较后阶段统一决定是否停止。

    核心原则：

    1. 发生异常的指令之前的老指令允许完成；
    2. 异常指令及其之后的新指令不能产生错误副作用；
    3. 一旦异常到达提交位置，处理器停止或报告状态。

    完整 PIPE 控制中还会涉及：

    M_bubble：阻止异常后的指令继续提交
W_stall：异常到达 W 后冻结最终状态

    14. 性能分析：CPI

    14.1 基本定义

    CPI = Cycles Per Instruction
    = 执行一条指令平均需要的时钟周期数

    理想流水线稳态：

    CPI ≈ 1

    设：

    实际指令数 = Ci
气泡数     = Cb
总周期数   ≈ Ci + Cb

    则：

    CPI = (Ci + Cb) / Ci
    = 1 + Cb / Ci

    将主要气泡来源分开：

    CPI = 1 + lp + mp + rp

    其中：

    • lp：Load/Use penalty；
    • mp：Mispredicted branch penalty；
    • rp：Return penalty。

    14.2 惩罚项计算

    某类 penalty
= 该类指令频率
× 触发冒险的条件概率
× 每次触发产生的气泡数

    示例：

    项目 指令频率 条件频率 每次气泡 贡献
    Load/Use 25% 20% 1 0.25×0.20×1=0.05
    分支误预测 20% 40% 2 0.20×0.40×2=0.16
    ret 2% 100% 3 0.02×1×3=0.06 
    总 penalty = 0.05 + 0.16 + 0.06 = 0.27
CPI = 1.27

    该例中最大的性能损失来自分支误预测。
